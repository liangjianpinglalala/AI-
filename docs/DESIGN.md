# 网站设计方案

## 一、产品目标

用户输入一个古诗名或成语，系统全自动（零人工干预）生成一个讲解动画视频，包含：脚本、配音、画面、字幕，最终剪辑导出成片。

## 二、整体架构

```
┌─────────────┐      ┌──────────────────┐      ┌─────────────────────┐
│   前端 SPA   │─────▶│  API 网关/后端服务  │─────▶│   任务队列 (Redis)   │
│ (Next.js)   │◀─────│   (FastAPI)       │◀─────│  Celery / RQ worker  │
└─────────────┘ 轮询/ └──────────────────┘      └──────────┬───────────┘
                 WS                                        │
                                                            ▼
                                              ┌─────────────────────────┐
                                              │   Agent 编排层（Claude）  │
                                              │  Script→TTS→Image→Edit  │
                                              └─────────────────────────┘
                                                            │
                        ┌───────────────┬───────────────┬──┴──────────┐
                        ▼               ▼               ▼             ▼
                   Claude API     TTS API(配音)    文生图/图生视频API  ffmpeg/Remotion
                                                                     (本地剪辑渲染)
                                                            │
                                                            ▼
                                              对象存储(视频/音频/图片) + Postgres(任务/元数据)
```

## 三、Agent 流水线

1. **内容检索与校验**：判断输入类型（诗词/成语），结合本地可信数据源 + Claude 组织语言，输出结构化知识（原文、作者、背景、含义），避免模型凭记忆编造。
2. **脚本生成**：Claude 生成结构化分镜 JSON（旁白、字幕、画面 prompt、时长、转场）。
3. **配音（TTS）**：逐场景合成语音，读取真实时长用于反推画面/字幕时长。
4. **画面生成**：文生图生成古风插画（MVP），Ken Burns 效果做动态感；进阶阶段接图生视频。
5. **字幕与时间轴对齐**：按音频时长切分，或用 Whisper 强制对齐获取精确时间戳。
6. **剪辑合成**：ffmpeg 拼接图片/音频/字幕/转场为完整 mp4。
7. **导出发布**：上传对象存储，返回可访问 URL。

全流程由状态机驱动，每一步独立可重试、可缓存，而非单个大 prompt 一次性生成。

## 四、前端设计

- 技术栈：Next.js + TailwindCSS
- 页面：首页（搜索）、生成进度页（分步进度条）、结果页（播放器+知识卡片+下载）、作品库/画廊页

## 五、后端设计

- FastAPI（Web API）+ Celery/Redis（异步任务队列）+ PostgreSQL（任务状态、作品缓存）
- 对象存储 + CDN 存放生成的音频/图片/视频

## 六、GitHub 发布方案

- Monorepo：`frontend/` `backend/` `agent/` `infra/` `docs/`
- GitHub Actions 跑 lint/build
- 前端部署 Vercel；后端+Worker 容器化部署到具备常驻 CPU 资源的平台（ffmpeg 渲染不适合 Serverless）

## 七、主要风险

- API 调用成本（靠缓存复用+限流控制）
- 内容准确性（RAG 而非纯模型记忆）
- 生成耗时的用户体验设计
- 零人工干预下的质量保证（自检 Agent 校验脚本/字幕/时长匹配）
